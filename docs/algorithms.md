# Как считает ядро

Устройство `core/` и принятые в нём решения. Модули и стенды — в [development.md](development.md),
что видит пользователь — в [README](../README.md). Ядро работает на голом Node и в воркере, про браузер
и SillyTavern не знает.

## Разбор текста (`tokenize`, `strip`)

- Из сообщения вырезаются HTML и разметка вместе с содержимым атрибутов (иначе внутренности `img src`
  и `div style` попадают в топ), промпты картинок и блоки инфопанелей (эвристика: теги, блок кода,
  таблица). Видимый отчёт «что посчитано прозой» и переключатель есть в панели.
- Имена персонажей и персоны берутся из самого чата и попадают в стоп-лист автоматически.
- Русский: `ё → е` до стемминга, затем Snowball. Латиница: Porter2. Лемматизатор не используется
  (словари слишком тяжёлые для вкладки). Список исключений стеммера (склейки и разлепленные видовые
  пары) живёт в `core/tokenize.mjs` и пополняется по мере встреч.
- Пользователю основа не показывается: хранится «ключ основы → счётчик + самая частая живая форма».

## Обороты (`ngrams`, `cvalue`)

- Основы интернируются в 32-битные идентификаторы, оборот хешируется скользящим 53-битным хешем
  (на 32 битах ложные склейки попадали бы в топ).
- Одиночные обороты отсеиваются блум-фильтром. Пока прозы меньше 50 тысяч слов, счёт идёт в обычной
  `Map` без отсева; при переходе счётчики переливаются в таблицу открытой адресации со сдвигом на
  единицу. Из-за блума все частоты занижены ровно на единицу, при выдаче прибавляется единица.
- Вложенные обороты схлопываются по C-value (только внутри чата, внешний корпус не нужен). Меры
  ассоциации (PMI, log-likelihood) не используются: PMI выталкивает наверх редкое.
- Кандидат в топ: частота не меньше 3 и минимум два разных сообщения («номер первого вхождения не равен
  номеру последнего» — множество номеров в слоте не хранится).

## Разнообразие (`diversity`)

MATTR с окном 50 — основная цифра, MTLD — вторая. Yule's K наружу не показывается. Окно 50 зафиксировано
навсегда: значения при разных окнах несравнимы.

## Самоповтор (`similarity`)

Четырёхсловные шинглы по основам, мера — containment относительно нового сообщения (Жаккар даёт ложный
отрицательный ответ, когда короткое сообщение повторяет кусок длинного). Показывается длина самого
длинного дословно повторённого фрагмента, а не коэффициент; подсветка идёт по живым формам. Порог не
абсолютный, а от распределения чата. Ретроспективный проход квадратичен, инкрементальный — нет.

## Индекс (`index`)

Сводная цифра из компонентов с якорями нормировки; версия формулы (`FORMULA_VERSION`) хранится рядом с
данными. До 50 тысяч слов прозы индекс помечается черновым.

## Правило для промпта (`prompt.mjs`)

Вставка выключена по умолчанию и подписана ценой в токенах. Формат по умолчанию — правило «прежде чем
писать ответ, сверь задуманное», а не голый список запретов: список работает как подсказка модели.
Шаблон редактируется по одному на формат. В правило попадают обороты, свежие по `lastMessage`
(`FRESH_SPAN = 30`), затихшие отсеиваются, два места хвоста ротируются раз в `ROTATE_EVERY = 10`
сообщений. Отдельный формат экспорта — машиночитаемый список.

## Карточка PNG (`card/`)

Рисуется на canvas вручную. Масштаб ограничивается расчётом по лимиту площади холста (iOS Safari),
размеры холста обнуляются после экспорта, отдача через `toBlob`. Ширина текста — только `measureText`
(кириллица шире латиницы), высота строки из метрик шрифта. Отдача: системный шаринг с проверкой
поддержки, запасной вариант — скачивание.

## Воркер (`worker.js`)

Сессия ядра живёт в воркере: полный проход — один неразрывный кусок, чанками его не разбить. Отмена —
поколениями, досчёты — цепочкой, `drop` при смене чата. Запасной путь на главном потоке уступает
интерфейсу и честно сообщает об этом в панели.
